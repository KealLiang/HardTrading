# 龙头条件1「先跌后涨」改造 — 背景与实现备忘

> 供新对话实现用。当前 **代码已回滚**，`analysis/ladder_chart.py` 仍为「近 30 日整体涨幅」口径。  
> 关联文档：[概念分组与龙头筛选逻辑说明.md](../概念分组与龙头筛选逻辑说明.md)

---

## 1. 需求一句话

**条件1** 的长周期涨幅判断，从「近 30 个交易日首尾整体涨幅 ≥ 阈值」改为：

> 近 **30 根有效 K** 内，存在一段 **收盘价** 涨幅（先低后高）≥ 阈值；允许先跌后涨，首尾整体涨幅可以不达标。

**仅改条件1**；条件2、全局门槛、名额、大龙股、排序字段等保持原语义（见下文「不受影响」）。

---

## 2. 当前代码（回滚后现状）

### 2.1 入口与参数

- 函数：`select_leader_stocks_from_concept_groups`（`analysis/ladder_chart.py`）
- 全局参数（约 111–141 行）：
  - `PERIOD_DAYS_LONG = 30`
  - `PERIOD_DAYS_CHANGE = 10`（短周期，用于 `short_period_change` 等）
  - `MIN_SHORT_PERIOD_CHANGE_FOR_LEADER = 30.0`（主板条件1下限）
  - `MIN_SHORT_PERIOD_CHANGE_FOR_LEADER_NON_MAIN = 37.0`（非主板）
  - 条件2：`LEADER_SECOND_WAVE_MIN_RANGE_PCT_MAIN/NON_MAIN`，窗口 `PERIOD_DAYS_VERY_LONG = 60`
  - 全局近 **3 日** 涨幅上限：`MAX_ULTRA_SHORT_PERIOD_CHANGE_*`（13% / 19%），**条件1、2 都要过**
  - 大龙股：`LEADER_EXTRA_LONG_PERIOD_THRESHOLD = 100%`（不占名额）

### 2.2 条件1 现状（`check_change_threshold` 内）

```text
cond1_change_ok = long_period_change >= 下限
condition1 = cond1_change_ok AND is_ma_trend_rising(stock_code, end_date)
```

- `long_period_change` 来自 `calculate_stock_period_change`：**固定 30 根有效 K**，**第一根开盘价 → 最后一根收盘价** 的整体涨跌幅。
- 典型漏网：前半个月跌、后半个月涨 40%，首尾算下来可能只有 +5%，**过不了条件1**。

### 2.3 条件2（不动）

```text
condition2 = is_leader_second_wave_long_ok(...)  # ladder_chart_helpers.py
return condition1 OR condition2
```

二波/老牌：近 60 日振幅 + MA10~MA20 带 + 方向约束等，与条件1 **OR** 合并。

### 2.4 其它门槛（与条件1并列，非 OR）

| 门槛 | 说明 |
|------|------|
| 连板 | 主板 `max_board_level >= 1`，非主板 `>= 0` |
| 近3日涨幅 | 严格 `<` 13% / 19%（全局） |
| 活跃股 | `SELECT_LEADERS_FROM_ACTIVE_ONLY=True` 时只从未折叠股中选 |
| 概念组 | 排除 `默默上涨`；按概念组活跃度分配名额 |

组内排序仍用：`long_period_change` → `short_period_change` → `max_board_level`（整体 30 日涨幅仍影响排序，**即使条件1改用段涨幅**）。

## 3. 目标行为（已确认口径）

### 3.1 段涨幅算法（方案 A，收盘价）

在截止复盘日 `end_date` 前，取近 **30 根有效 K** 的 **收盘价** 序列（与条件2 一样跳过无效/停牌 K，逻辑可复用 `is_leader_second_wave_long_ok` 的扫 K 方式）。

**最大段涨幅**（允许先跌后涨）：

```text
维护迄今最低收盘 min_close
逐日: gain = (close / min_close - 1) * 100%
max_segment_gain = max(gain)
```

等价于：存在更早收盘 c_i、更晚收盘 c_j（i<j），使 `(c_j/c_i - 1)*100` 最大。

**不用**最高/最低价，用户明确要求 **统一用收盘价**。

### 3.2 条件1 新逻辑（仅替换 `cond1_change_ok`）

```text
segment_gain = max_close_segment_gain_pct(stock_code, end_date, PERIOD_DAYS_LONG)
cond1_change_ok = segment_gain is not None AND segment_gain >= 下限(主板/非主板)
condition1 = cond1_change_ok AND is_ma_trend_rising(...)
```

- `end_date` 缺失时：条件1/2 均不成立（保持现有行为）。
- **不影响条件2**：仍为独立分支后 `|` 合并。

### 3.3 建议实现位置

- 新函数：`max_close_segment_gain_pct` → 放在 `analysis/helper/ladder_chart_helpers.py`（与 `is_leader_second_wave_long_ok` 同级，`@lru_cache`，在 `clear_helper_caches` 里 `cache_clear`）。
- 调用：仅 `check_change_threshold` 内替换 `long_period_change >= 下限` 那一行。
- **不要**改 `long_period_change` 列的计算（排序、大龙 100%、Excel 展示仍用整体 30 日涨幅）。

## 4. 曾讨论、已回滚的可选收紧（非本轮必做）

对话中曾实现后又随龙头逻辑 **整体回滚** 的项，可作为「放宽条件1 后候选过多」时的收紧方向：

| 方向 | 说明 | 作用范围 |
|------|------|----------|
| 条件1 **近10日涨幅上限** | `short_period_change < 35% / 45%`（`PERIOD_DAYS_CHANGE=10`） | **仅条件1** |
| 条件1 **近30日整体涨幅上限** | 曾短暂用过，用户改为要 10 日上限 | 已废弃 |

用户原话：*「改动相当于是放宽入选条件，不希望候选太多，需要收紧其他方面，目前没想好，先实现段涨幅一版看看。」*

**本轮建议**：先只做段涨幅，不加新收紧；跑复盘看候选数量后再定。

    max_gain = 0.0
